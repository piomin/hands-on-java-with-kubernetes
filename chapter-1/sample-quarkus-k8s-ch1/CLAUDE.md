# CLAUDE.md: sample-quarkus-k8s-ch1

Walkthrough of the Quarkus exercise from chapter 1 of the book "Java with Kubernetes in Action" (`../../../java-with-kuberneters-in-action-book/chapter-01`, sections "Generate an App using Quarkus CLI", "Deploy Quarkus Application on Kubernetes", "Expose an App Outside a Cluster"). Follow the book; the code in this directory is the finished result.

## Prerequisites

- JDK 25, Maven 3.9+, `kubectl`, `minikube` (docker driver), Quarkus CLI (`quarkus`) only for generating the project from scratch.
- A Docker Hub account and `docker login` done. Images go to `docker.io/<DOCKER_USERNAME>/sample-quarkus-k8s-ch1`. Get the login with `docker info | grep Username` and use it as `<DOCKER_USERNAME>`.
- Unless told otherwise, the target cluster is a local Minikube. Check `kubectl config current-context` is `minikube` before any deploy.

## Step by step

1. Generate the project (skip if the code already exists):
   ```shell
   quarkus create app pl.piomin:sample-quarkus-k8s-ch1 \
     --extension='rest,container-image-jib,kubernetes'
   ```
   The generated `GreetingResource` serves `GET /hello`.
2. Build, push the image and deploy:
   ```shell
   mvn clean package \
     -Dquarkus.kubernetes.deploy=true \
     -Dquarkus.container-image.group=<DOCKER_USERNAME>
   ```
   Without `quarkus.container-image.group` the image prefix is the OS account name and the `Deployment` points to an image that does not exist. Quarkus creates a `Deployment` and a `Service` (`ClusterIP`, port `80`).
3. Verify:
   ```shell
   kubectl get pod
   kubectl get svc sample-quarkus-k8s-ch1          # ClusterIP, 80/TCP
   kubectl port-forward svc/sample-quarkus-k8s-ch1 8080:80
   curl http://localhost:8080/hello                # Hello from Quarkus REST
   ```
4. Scale (as in the book): `kubectl scale deploy sample-quarkus-k8s-ch1 --replicas=3`, then `kubectl get pod`; scale back to 1 afterwards.
5. Expose the service on port 8080 instead of 80: add to `src/main/resources/application.properties`
   ```properties
   quarkus.kubernetes.ports.http.host-port = 8080
   ```
   rebuild and redeploy with the command from step 2, then:
   ```shell
   kubectl get svc sample-quarkus-k8s-ch1         # 8080/TCP
   kubectl port-forward svc/sample-quarkus-k8s-ch1 8080
   curl http://localhost:8080/hello
   ```
6. Clean up only on explicit user request, or after the user confirms at the end of the run:
   ```shell
   kubectl delete -f target/kubernetes/kubernetes.yml
   ```

## Final report

At the end of a run, always print a short summary for the user with these three parts, then ask whether to clean up:

1. **What was built and deployed:** the image (`<DOCKER_USERNAME>/sample-quarkus-k8s-ch1:1.0-SNAPSHOT`), the `Deployment` and the `Service` generated by the Quarkus Kubernetes extension (port `80`, or `8080` after the `host-port` property).
2. **Where it is:** cluster context (`minikube`), namespace (`default`), registry (`docker.io/<DOCKER_USERNAME>`), the manifest file `target/kubernetes/kubernetes.yml`.
3. **How to test it:** `kubectl get pod,svc`, `kubectl port-forward svc/sample-quarkus-k8s-ch1 8080:80` (or `8080` after the property change), `curl http://localhost:8080/hello` (expected `Hello from Quarkus REST`). Say which of these you ran and what they returned.

## Rules for agents

- Build and test without side effects first: `mvn clean package` (no `quarkus.kubernetes.deploy`) only compiles, runs tests and generates the manifest. Do not set `quarkus.container-image.push` or `quarkus.kubernetes.deploy` unless the deploy is intended.
- Ask the user before anything outward-facing: pushing to Docker Hub, deploying to a cluster, deleting or recreating a Minikube profile.
- Do not clean up (`kubectl delete`, `skaffold delete`, `helm uninstall`) unless the user explicitly asks for it. At the end of a run, ask the user whether to clean up and wait for the answer.
- Never deploy to a cluster other than the local Minikube unless the user says so.
- Do not commit `target/`.
- When a step fails or an output differs from the book, fix the code or this file so they agree, and mention it in the report.
